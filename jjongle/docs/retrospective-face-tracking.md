# 얼굴 인식 및 추적 기술 고도화 회고 (Face Tracking Retro)

본 문서는 쫑글 프로젝트의 핵심 기능인 **얼굴 인식 및 플레이어 추적 기술**이 어떤 단계를 거쳐 발전해왔으며, 최근 직면했던 문제와 최종 해결 방안은 무엇이었는지 정리합니다.

---

## 1. 기술 변천사 요약

### 1단계: 웹소켓 기반 서버 측 이미지 처리 (초기 상태)
*   **구현 방식:** 클라이언트가 카메라 프레임을 지속적으로 JPEG/Base64 데이터로 변환하여 WebSocket을 통해 서버에 전송. 서버에서 Python 기반의 YOLOv8 및 DeepSORT 서버를 구동해 얼굴 검출, 플레이어 추적, O/X 영역 판정을 수행.
*   **문제점:**
    *   **네트워크 과부하:** 다수의 클라이언트가 초당 수십 장의 이미지를 동시에 업로드하면서 네트워크 대역폭 부족 문제 발생.
    *   **서버 비용 및 인프라 과부하:** 서버 사이드에서 실시간으로 프레임을 추론해야 하므로 서버 호스팅 비용과 부하가 급증.
    *   **지연 속도(Latency):** 네트워크 전송 및 서버 처리 지연으로 인해 실시간 상호작용성 하락.

### 2단계: 온디바이스(On-Device) ML Kit 도입 (Refactoring)
*   **구현 방식:** CameraX `ImageAnalysis`와 구글의 **온디바이스 ML Kit Face Detection**을 활용해 모바일 기기 내에서 직접 얼굴을 검출. 얼굴의 중앙 좌표 `(x, y)`를 구해 로컬에서 O/X 영역을 판정한 뒤, 결과 JSON 페이로드만 서버로 송신하도록 변환 ([ox-on-device-mlkit.md](file:///Users/choejin-u/JJongle-Android/jjongle/docs/ox-on-device-mlkit.md) 참고).
*   **문제점:**
    *   **ML Kit Tracking ID의 한계:** ML Kit이 제공하는 `trackingId`는 기기 성능이나 얼굴의 각도, 순간적인 가려짐(Occlusion), 빠른 움직임에 의해 쉽게 손실되고 재할당됨.
    *   이로 인해 게임 중에 아이들이 움직이면 플레이어 ID가 계속 바뀌어 기존 스코어나 프로필 매핑이 끊기는 심각한 UX 문제 발생.

### 3단계: 기기 내 SORT 알고리즘 도입 및 칼만 필터 예측 오류
*   **구현 방식:** 기기 내에서 자체적으로 플레이어 ID를 유지하기 위해, 대표적인 다중 객체 추적(MOT) 알고리즘인 **SORT(Simple Online and Realtime Tracking)**를 Kotlin으로 구현 (`FaceReidentifier`, `KalmanBoxTracker`, `HungarianAlgorithm` 도입). 칼만 필터를 통해 다음 프레임의 위치를 예측하고, 새로 감지된 상자와의 IoU(Intersection over Union) 비용 행렬을 헝가리안 알고리즘으로 매칭.
*   **문제점 (칼만 필터 예측 실패 버그):**
    *   기존 `KalmanBoxTracker` 구현체는 성능 최적화를 위해 **대각 공분산(Diagonal Covariance)만 사용하는 간이 방식**을 채택.
    *   이로 인해 **위치 관측값으로부터 이동 속도(Velocity)를 역산하고 업데이트하는 칼만 필터의 핵심 코드가 누락**됨.
    *   속도가 항상 0으로 유지되어 칼만 필터의 예측(`predict()`) 상자가 실제 물체를 따라가지 못하고 항상 제자리에 멈춰 서 있는 심각한 버그 발생.

## 2. 최종 문제 해결 (Phase 1 SORT 알고리즘 정상화)

원래는 외형 특징 기반 매칭(DeepSORT의 ReID 모델)까지 안드로이드에 포팅하려 했으나, 딥러닝 모델 탑재 시 모바일 성능 저하가 우려되었습니다. 분석 결과 **칼만 필터의 수학적 모델링만 정상화(SORT 알고리즘 완성)해도 추적 정확도가 충분히 보장**된다고 판단하여 1단계를 실행했습니다.

### 수정 핵심 내용
*   [KalmanBoxTracker.kt](file:///Users/choejin-u/JJongle-Android/jjongle/app/src/main/java/com/ssafy/jjongle/presentation/vision/KalmanBoxTracker.kt) 파일을 전면 수정하여, 각 차원(`cx`, `cy`, `w`, `h`)에 대해 **독립적인 1D 등속 운동 칼만 필터(상태 벡터 [위치, 속도]^T, 2x2 공분산 행렬)**를 정상적으로 적용하였습니다.
*   이제 관측값(얼굴 박스 위치)이 갱신될 때마다 **속도 성분이 수학적으로 올바르게 추정 및 보정**됩니다.
*   이로 인해 얼굴이 빠르게 이동하거나 일시적으로 프레임에서 유실되더라도, 관측된 속도 벡터를 토대로 다음 프레임 위치를 정확하게 관성 예측함으로써 IoU 매칭률이 극적으로 향상되었습니다.

---

## 3. 요약 및 시사점
*   초기 **무거운 서버 추론 모델(YOLO+DeepSORT)** 구조에서 **가볍고 실시간성을 보장하는 온디바이스 하이브리드 추적 구조(ML Kit Face Detection + Kotlin SORT)**로의 전환을 성공적으로 완수했습니다.
*   네트워크 트래픽을 거의 제로에 가깝게 절감하면서도, 버그 수정된 칼만 필터 덕분에 별도의 임베딩 추출 모델 없이도 아이들의 역동적인 움직임을 안정적으로 추적할 수 있게 되었습니다.
